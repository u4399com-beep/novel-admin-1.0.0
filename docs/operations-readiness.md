# 运营就绪评估报告（Operations Readiness Assessment）

> 生成：R134 轮（2026-11-08）。评估人：Z.ai Code。
> 方法：以仓库实际代码、worklog.md（R100-R133）、18 次沙箱重置自愈实战、引擎/库运行快照为事实来源，逐维度核查打分；不采信未验证的声明。
> 结论速览：**个人/内网自用运营：已达标准；对外公网商业运营：未达**——缺认证、TLS、自动备份、外部告警四件基础设施，以及版权合规论证（见 §H）。

## A. 服务可用性与自愈（★★★★☆）

**证据**（全部实战验证）：
- 三服务（backend :3000 / scraper :3030 / stealth :3031）+ watchdog 反脆弱守护（R116：连续失败闸/防抖/fd 泄漏根修）。
- 舰队全生命周期自持：E26 空缺自动建任务（5min 巡）、E21 paused 自动复活、E23 巡检联动复活、R133 引擎不可达零预算恢复通道（autoResumeEngineTasks，R134 轮实证：热替换重启后 19 任务 paused→100s 内 16 条自动回 running，零人工）。
- 18 次沙箱重置自愈，最近 4 次全形态（进程+bin+Go+db+venv+chromium 全灭）恢复 ~20 分钟；`docs/recovery-playbook.md` 225 行逐步可执行，含每坑症状识别。
- 互监护：backend runner 30s 探活引擎，杀残留托孤拉起。

**Gap**：
- [P1] watchdog 是「进程级」探活；缺「页面级」外部拨测（Uptime-Kuma 类）——backend 进程活着但页面白屏时无人知晓。
- [P2] 首页/详情页未配置错误率 SLO 数值目标（建议：可用性 ≥99%（月），P95 TTFB ≤1.5s——当前实测首页 <200ms，达标但未制度化）。

## B. 数据质量与完整性（★★★★☆）

**证据**：
- 数据清洗三轮（R131-R133）全字段闭环：书名（SEO 尾缀词表+「小说」保守剥）/作者/分类（ListItem 接线）/简介（转载尾注+书友推荐语+截断容错+微博孤儿尾四族锚点）/章节标题/正文（cleanx 行级规：JS 残迹/非法注释）。引擎挡新 + backend 回填洗存 + 存量手修三层。
- R133 终扫：书名 SEO 0 / 简介尾注 0 / 全库 1165 书。
- 章序三层根修（reorderRefPairs 全局升序）、首章健康审计 8/8（R130）。

**Gap**：
- [P1] 全库 resort+audit 终验仍为「list 任务批量终态后一次性」待办——建议改为周期化（每完成 N 个 list 任务触发一轮），否则终验永远追赶变化数据。
- [P2] 简介超短/空简介占比无指标（清洗管「脏」，「缺」未量化）。

## C. 采集能力与反反爬（★★★★☆）

**证据**：
- 7 级策略链（fetch-browser/ua-rotate/mobile/spider/curl-imp/got-scraping/playwright cloak 兜底）+ 按主机策略亲和提位。
- E3-E26 增强族：指纹一致性、会话粘性、cf-mitigated 探测、出口维度熔断、出口池自愈（E18 五源+时延择优）、规则健康巡检（E19）、过盾有效状态回报（R122）、挑战强/弱特征分级。
- 引擎成功率 98.3%（1370/23，R134 快照）；历史最优 96.5%（7258/264）。
- 站点覆盖：25 规则（20 enabled）×20 host；blqiuge.cc 全链实测入库（规则 34，R132）。
- per-host 任务并发准入（R133）：同 host 任务齐发→域限速排队饱和→熔断循环根因消除，效率与封禁保护兼顾。

**Gap**：
- [P1] CF 交互式挑战硬骨头维持任务级 bounded 自愈（101kks 风暴期、pilishuwu 依赖过盾 cookie 回放）——已定性可接受，但长期不放行需代理池补种预案（§6.3 已载）。
- [P2] duckduckgo pseo 探测 fail 积聚为已知熔断行为（重启清零重探测），无成本无风险，可不做。

## D. 性能与容量（★★★☆☆）

**证据**：
- 吞吐：12.2k 章/h 混合调度窗口（R131 实测）；R133 车道解冻修复后满预约形态理论 ~1800 章/h/源站（单 IP 礼貌约束下）。
- QueueMs 丢失根修（R131）：R114 服务耗时修复真正落地章路径，车道冻结→呼吸式饱和收敛。
- 库规模：单机 SQLite，926k 章节行（R134 快照）查询无压力；正文 3.1k 行按需填充。
- R133 E2E：首页 42 本、详情页 26 章链、零 console error、移动端 390px 零溢出。

**Gap**：
- [P1] SQLite 单文件容量与并发写上界未压测（百万章级已实证无压力，千万级未知）；增长到 WAL >10GB 时的 checkpoint 策略未定义。
- [P2] 无慢查询日志/DB 性能基线（现状够用，运营规模化前补）。

## E. 安全（★★☆☆☆）——最大短板

**现状**：
- 引擎侧：SSRF 逐跳校验、insecureTLS 规则级显式开关、代理出口独立记账——防护完善。
- 管理面：**全部管理 API（规则 CRUD/任务 CRUD/设置/导出）零认证**。Caddy :81 单端口全转发，公网部署即：任意访客可增删规则、启动任意任务、读全库。
- 传输：无 TLS（Caddyfile :81 明文 HTTP）。
- 密钥：LLM key 明文 env 文件；GitHub PAT 已在对话多轮暴露（用户侧已提醒轮换）。
- 无审计日志（谁改了规则/设置无记录）。

**整改清单（P0，公网运营前置）**：
1. 管理 API 加认证：至少 `X-Admin-Token` 环境变量 + Caddy `@admin` matcher 反代层校验（半天工作量，Caddy 层可先行）。
2. TLS：Caddy `tls` 指令或外部 LB 终结。
3. 公开读接口与管理写接口分离路径（`/api/scrape-*` 仅内网/带 token）。
4. PAT/LLM key 轮换+最小权限。

## F. 可观测性（★★★☆☆）

**证据**：
- `GET /api/stats`（引擎主机×策略两维四类计数+Top fail）、`/api/host-health`、`/api/health`（backend 含 dbOk/ruleHealth 摘要）、rulehealth 45min 巡检三态落库、规则面板「健康」列+手动触发按钮。
- watchdog 内存水位观测（MemAvailable 警戒留档）。

**Gap**：
- [P1] 无告警通道：所有自愈/巡检/熔断只写日志与 DB，人不在场=事件黑洞。最小整改：规则不健康/任务批量 paused/服务重启三类事件 webhook 推送（可选 Bark/飞书/邮件）。
- [P1] 指标无历史：stats 为自启动累计，重启清零——无法回答「上周成功率多少」。最小整改：backend 定时（10min）把引擎 stats 快照落表（复用 RuleHealth 表模式）。
- [P2] 无外部拨测（同 §A gap）。

## G. 运维与恢复（★★★★☆）

**证据**：
- `scripts/deploy-cn.sh` 8 步全链（含 R131 stealth 侧车补全、cloakbrowser<0.7 锁版、镜像候选链+断点续传）；`bootstrap-cn.sh` curl/wget 双引导；R133 审阅+R134 API 兼容实证（0.6.5 `get_chromium_version()` 存活）。
- recovery-playbook 每坑症状+修复路径；18 次实战走通；本轮（18th）首次「bin 全灭+GitHub URL 变迁」形态已补录（CloakHQ/cloakbrowser 权威 URL）。
- 预构建快速路径 + E26 空库自播种（25 规则）+ 9 分类/首页配置/任务舰队全自动重建。

**Gap**：
- [P1] **备份自动化未启用**：deployment.md §备份有现成命令（sqlite3 .backup + cron + 14 天保留），沙箱/新服务器均未落地。一行 crontab 的事，运营必须做。
- [P2] 备份恢复演练无记录（有命令无演练=未验证的备份）。

## H. 合规与法律（★★☆☆☆）——运营决策级风险

**现状**：
- 爬虫行为合规（代码内建、不可配置绕过）：≥1.2s 域间隔、robots warn-only、无验证码破解/登录伪造/付费绕过、仅抓规则显式配置公开页面。
- 内容合规：**未论证**。采集对象为第三方小说站（笔趣阁系等本身多为盗版聚合站），再分发内容的版权链条不清晰。「原创小说网站」定位与实际以采集为主的内容来源存在错位。

**运营前必须处置**：
1. [P0] 明确运营定位并法务评估：仅个人阅读/内网工具（风险自担）≠ 公网对外提供（侵权风险实质化）。
2. [P1] 若坚持公网：建立投诉-下架通道（DMCA 类）、仅缓存元数据+跳转原文站的技术方案评估、避免全文镜像。
3. [P1] 隐私：当前无用户系统、不采集用户数据（正面）；若加评论/账号需补隐私条款。

## 结论

**分级判定**：
- **Level 1「个人自用/内网服务」：达标。** 自愈、数据质量、采集能力、文档均已超出多数个人项目水准，可长期无人值守运行（E 家族闭环+watchdog+playbook 实证）。
- **Level 2「公网上线试运营」：未达。** 差 §E 四件套（认证/TLS/接口分离/密钥治理，~1-2 天工作量）+ §G 备份 cron（~10 分钟）+ §F 告警 webhook（~半天）。全部做完即可上线试运营。
- **Level 3「规模化商业运营」：未达，且有 §H 版权前置风险**——先法务后技术。
